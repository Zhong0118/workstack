# macOS 窗口切换基准

## GUI 管理中心

使用 `WW_MEASURE=1 Scripts/integration-check.sh release`。脚本在新建的临时目录中构建 QA 专用应用及两个夹具，校验测试进程身份，只允许这两个应用进入窗口后端。测试会轮流置前夹具窗口，需在允许前台切换的已登录桌面运行。无辅助功能权限时仍取空闲样本，随后以 77 退出。脚本结束时清理临时包、配置和恢复日志。

2026-11-14 本机对照使用 Apple M4、16 GiB、macOS 27.0.1（26A434）、Swift 6.1.2 和两台显示器。工作区 A 有两个不同进程的标签及一个分屏窗格，B 有一个窗口。每个场景预热后交替切换 20 次。旧版取自 `5579b91`，在该提交的源码副本中加入相同的测试目录、进程限制及计时代码。

- **命令完成**从调用管理中心的 `selectTab` 或 `activate` 起算，到 AX 操作、业务状态提交完成且 `busy` 归零。采样间隔 1 ms。
- **界面模型确认**延续同一计时，等待窗口观察结果显示预期焦点；专注模式还检查正确的窗口集合已最小化；标签场景检查外部浮条可见。每 10 ms 检查一次。这两个口径均不包括鼠标、键盘分发、合成器最终显示帧。
- **资源**为 QA 管理中心进程的 CPU 时间／墙钟耗时及定点采样 RSS，单核满载为 100%。计入等待模型确认和采样本身的开销；不含夹具和 WindowServer。每档 P50 取中间两数均值，P95 取第 19 个值。

| 场景 | 版本 | 命令 P50 / P95 (ms) | 模型确认 P50 / P95 (ms) | CPU (%) | RSS (MiB) |
|---|---|---:|---:|---:|---:|
| 跨应用标签，收起非活动标签 | 旧 | 778.5 / 803.8 | 778.6 / 803.8 | 15.4 | 108.8 |
| 同上 | 新 | 788.3 / 821.9 | 788.4 / 821.9 | 16.7 | 111.7 |
| 专注工作区，收起旧成员 | 旧 | 1020.7 / 1049.4 | 1052.2 / 1150.9 | 18.0 | 121.5 |
| 同上 | 新 | 1033.2 / 1080.1 | 1033.2 / 1080.1 | 22.2 | 116.2 |
| 暖布局，保留旧工作区可见 | 旧 | 186.3 / 211.5 | 279.4 / 331.8 | 52.1 | 104.1 |
| 同上 | 新 | 165.7 / 191.5 | 165.8 / 191.5 | 67.5 | 103.7 |

暖布局的模型确认 P95 缩短 140.3 ms（42.3%）。专注模式的模型确认 P95 缩短 70.8 ms（6.2%），命令耗时 P95 增加 30.7 ms。跨应用标签的模型确认 P95 增加 18.1 ms（2.2%）。本轮切换期间新版本的 CPU 百分比均较高，包括在更短时间内完成的暖布局。系统最小化及恢复动画仍在标签和专注模式的计时范围内。

最终 Release 验收另用独立 AX 客户端按下管理中心外部浮条的目标标签按钮。从发送 AXPress 到收到目标窗焦点的模型回报为 822.4 ms（1 次）。跨进程共用系统单调时钟，计时排除辅助进程启动及控件查找，未计物理鼠标分发与最终屏幕帧。

空工作区、管理中心窗口打开、预览关闭、无夹具进程时，旧版 15.67 s 的平均 CPU 为 0.14%，RSS 从 118.1 降至 106.6 MiB；新版 15.52 s 的平均 CPU 为 0.20%，RSS 从 100.8 升至 113.9 MiB。隔离后端不会扫描用户应用，两次短采样均不能代表日常完整工作区或后台长期占用。

### 叠放标签（当前默认）

后台标签改为默认叠放在活动标签的位置，切换时只前置目标窗口；最小化后台标签成为可选项。下表取自同一台机器、同一次 `WW_MEASURE=1` 运行，跨应用标签每档 20 次，运行期间每秒采样一次 HID 空闲时间，全程无键盘鼠标输入。

| 场景 | 命令 P50 / P95 (ms) | 模型确认 P50 / P95 (ms) | CPU (%) | RSS (MiB) |
|---|---:|---:|---:|---:|
| 跨应用标签，叠放后台标签 | 145.2 / 155.1 | 145.3 / 155.1 | 36.7 | 150.5 |
| 跨应用标签，最小化后台标签 | 788.4 / 799.0 | 788.4 / 799.0 | 15.4 | 150.4 |
| 专注工作区，收起旧成员 | 1160.6 / 1194.8 | 1160.6 / 1194.8 | 19.2 | 151.0 |
| 暖布局，保留旧工作区可见 | 161.3 / 181.7 | 161.3 / 181.8 | 65.9 | 134.2 |

叠放切换的命令 P50 为最小化路径的 18%。剩余的约 145 ms 主要是跨应用激活到焦点确认的等待：把确认轮询从 0／50／150／300 ms 改成 8 ms 一次后，P50 没有可分辨的变化，这项改动已撤回。同一次运行的空闲样本为 15.23 s、平均 CPU 0.12%。

`WW_MEASURE=idle` 只取空闲样本并以 77 退出，不启动夹具，也不抢焦点。完整检查依赖焦点切换，运行期间有键盘鼠标输入时会在焦点校验处随机失败。

一次开发中的专注模式压力测试遇到 AX 状态校验失败，该轮没有产出完整工作区样本。表中的结果取自各场景完成 20 次的批次，仅能用作本机回归对照。下方历史探针开销涵盖的窗口数、焦点和布局命令、系统动画及 GUI 发布范围都与这些数据不同。

加入浮条淡入淡出和移动脱离后在同一台机器上重跑（全程无输入）：`tab_stacked` P50/P95 为 141.9/149.8 ms，空闲 CPU 0.13%，与上表一致。同一次运行里最小化标签为 663.9/680.5 ms、专注模式为 964.1/1146.0 ms，比上表快，原因未查明，浮条改动不在命令路径上，不应据此认为这两项变快了。

### 界面刷新成本

`WW_MEASURE=ui` 在隔离的 QA 实例里反复切换 `busy`（每 5 ms 一次，共 300 次），不启动夹具、不抢焦点，报告每次刷新的进程 CPU 时间，以及相对空转循环多占用主线程的时间。`WW_DEMO=1` 会预置三个空窗口组，让管理中心有内容可画。以下均为 Release、带 `WW_DEMO=1`、各三次：

| 版本 | 每次刷新 CPU | 主线程多占用 |
| --- | --- | --- |
| 改动前（手搭三栏，整个模型一个变更通知） | 13.1–13.6 ms | 21.6–22.4 ms |
| 换成系统侧边栏、工具栏、检查器后 | 24.9–25.3 ms | 未测 |
| 再改为按属性追踪、隔离 `busy`、缓存本地化字符串、设置页延后查询 | 3.0–3.3 ms | 约 0 ms |

改动前每次变更通知都会重建设置页，而设置页初始化时同步查询登录项状态和屏幕录制权限，在换成系统控件后的那一版采样里，这两次跨进程查询约占主线程样本的四成。主线程占用以 5 ms 的睡眠为余量，低于余量的刷新不会体现在这一列里。窗口标题变化仍会重算管理中心的主体，这一项没有单独计量。

界面刷新变便宜后，真实窗口上的切换也随之变快。同一台机器、Release、每档 20 次，连续两次运行（两次运行的前半段都检测到键盘或鼠标输入，所有步骤通过，两次结果一致）：

| 场景 | 改动前 P50 | 现在 P50 / P95（两次运行） |
| --- | --- | --- |
| 切换标签，叠放 | 141.9–145.2 ms | 76.4 / 88.2 ms，77.5 / 85.5 ms |
| 暖布局切换工作区 | 161.3–167.3 ms | 127.8 / 148.4 ms，122.1 / 147.3 ms |
| 切换标签，最小化 | 663.9–788.4 ms | 633.5 / 645.5 ms，634.6 / 673.7 ms |
| 专注模式切换工作区 | 964.1–1160.6 ms | 941.7 / 1029.1 ms，954.7 / 1035.9 ms |

叠放切换此前被判断为“剩余耗时主要是系统跨应用激活的等待”，这个判断不完整：命令在主线程上等待时，每次变更通知引发的界面刷新会推迟它继续执行，这部分约占原耗时的一半。只换系统控件、未改追踪方式的中间版本上，叠放切换为 171.0 / 176.4 ms。

## 历史后端探针

### 复现

在已登录的桌面上运行。需要给启动探针的应用或可执行文件授予“辅助功能”权限。只读模式在权限未授予时输出原因，写入测试在这种情况下以 77 退出。基准会在前台轮流聚焦专用测试窗口。

```sh
swift build -c release --product window-probe
.build/release/window-probe
.build/release/window-probe --smoke
.build/release/window-probe --benchmark
```

### 工作负载

- 每档在一个新的 AppKit 子进程中创建 10、30 或 60 个同标题标准窗口。探针监听真实桌面的窗口事件，通过子进程 PID 筛选并保存夹具窗口的 AX 引用。测试结束时退出该子进程并删除临时日志目录。
- 单窗口切换轮流选中两个已知窗口，通过 `WindowCoordinator` 执行显示和聚焦，读取目标进程的焦点窗口确认结果。
- 工作区切换轮流进入两组各四个窗口的暖布局，为每个窗格执行显示、布置、聚焦。预热阶段先用 AX 移动和缩放到指定坐标，测量阶段可以跳过位置已正确的写入。此前工作区的窗口保持可见。测量范围为真实控制器到 AX 确认，UI 输入、配置提交、SwiftUI 绘制和最终显示帧不计入。
- “全量读取”是同一版本的显式参照路径，每次切换前额外通过 AX 读取全部夹具窗口。“缓存”路径使用已发现的成员绑定，两种路径使用相同的业务命令及写后校验。
- 每个单元格 20 次连续切换。P50 为中间两个样本的均值，P95 为第 19 个有序样本。CPU 为探针的用户态和内核态 CPU 时间除以实耗时，单核满载为 100%。RSS 为切换前及每次切换后采样所得的最大常驻内存。两项都只计探针进程；夹具应用、WindowServer 和 GUI 管理中心的资源另计。RSS 可能漏掉采样间的峰值。
- 系统环境为 Apple M4、16 GiB RAM、macOS 27.0.1（26A434）、Apple Swift 6.1.2、两台显示器。系统调度、前台焦点竞争和各应用的 AX 实现都会影响结果。20 个样本用于本机回归对照，无法估计不同机器上的高分位分布。

### 实测结果

| 窗口数 | 切换对象 | 路径 | P50 (ms) | P95 (ms) | CPU (%) | RSS (MiB) |
|---:|---|---|---:|---:|---:|---:|
| 10 | 单窗口 | 全量读取 | 8.6 | 21.4 | 26.0 | 38.1 |
| 10 | 单窗口 | 缓存 | 5.2 | 12.4 | 16.8 | 38.1 |
| 10 | 四窗格工作区 | 全量读取 | 29.8 | 40.1 | 23.7 | 37.9 |
| 10 | 四窗格工作区 | 缓存 | 26.3 | 36.7 | 20.2 | 38.1 |
| 30 | 单窗口 | 全量读取 | 19.7 | 37.3 | 33.3 | 32.1 |
| 30 | 单窗口 | 缓存 | 9.3 | 62.4 | 8.3 | 38.3 |
| 30 | 四窗格工作区 | 全量读取 | 35.7 | 45.6 | 30.2 | 31.3 |
| 30 | 四窗格工作区 | 缓存 | 24.3 | 42.5 | 17.9 | 31.2 |
| 60 | 单窗口 | 全量读取 | 29.8 | 71.8 | 33.5 | 31.8 |
| 60 | 单窗口 | 缓存 | 4.3 | 7.6 | 19.8 | 31.3 |
| 60 | 四窗格工作区 | 全量读取 | 61.2 | 110.2 | 29.1 | 31.2 |
| 60 | 四窗格工作区 | 缓存 | 32.0 | 57.7 | 17.8 | 31.3 |

在 60 个夹具窗口时，缓存路径的单窗口 P50 从 29.8 ms 降至 4.3 ms，四窗格工作区从 61.2 ms 降至 32.0 ms。30 窗口的单窗口缓存 P95 达到 62.4 ms，高于全量参照 25.1 ms。

另一次独立的双窗口 smoke 检查通过了跨进程移动、缩放、最小化及恢复、精确聚焦和同进程兄弟窗口隔离。探针向自建子进程发送 SIGSTOP，在 241 ms 后得到 AX 超时，随后 SIGCONT 恢复同一窗口的读取。

`Scripts/integration-check.sh` 还会创建一个具备 bundle ID、进程启动时间和窗口 AXIdentifier 的测试应用。恢复探针最小化其中一个窗口并写入日志，关闭第一个观察器，再由全新观察器读取磁盘日志，核对身份并恢复目标窗口。这项检查已通过，目标窗口及同进程的另一个窗口均验证了最终几何与最小化状态。

历史版本另做了一次普通启动的 Release 管理中心取样。快速切换器关闭、管理中心保持打开、空工作区、预览关闭，连续 15.01 秒无操作，进程累计 CPU 时间增加 0.07 秒，约占单核 0.47%，RSS 从 108.7 MiB 变为 99.3 MiB。该样本计入 AppKit/SwiftUI 界面，和上表探针进程的 RSS 分开统计。短样本不代表长期后台占用上限。
