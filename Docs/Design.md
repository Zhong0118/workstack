# workstack

## 产品取舍

- [BetterStage](https://betterstage.app/) 的命名 Stage 横跨多台显示器。工作台采用持久化的逻辑工作区，并独立保存各组的目标显示器。
- [Panelet](https://panelet.app/) 将同一应用的不同窗口放进不同 pane。成员的主键采用逻辑窗口 UUID。应用标识用于筛选。
- [TileOrg](https://www.tileorg.com/) 展示了按项目切换一套窗口的流程。菜单栏采用项目入口。终端、编辑器、浏览器走相同的窗口发现路径。
- [WindowRanger](https://windowranger.com/) 将逻辑工作区与命令搜索结合。主界面用于组织，快速切换器用于找回工作上下文。
- [GroupShelf](https://group-shelf.com/) 展示了跨应用标签、拖动加入及窗口选择器。工作台使用独立面板，操作对象始终是原应用自己的窗口。
- [TrellisWM](https://trelliswm.app/) 的中心和边缘落点分别表示加入标签和创建分屏。编辑器沿用这套空间含义，递归计算布局。
- 评估了 [Rectangle](https://github.com/rxhanson/Rectangle) 的独立窗口管理器集成成本。这次使用系统框架自行实现，零第三方运行依赖。以上是公开交互资料，不能据此推断竞品的内部实现。

## 实现与验收

SwiftUI 管理中心 → Workbench 命令与操作串行化 → MacWindows → AX。平台回报窗口快照，经身份解析关联至逻辑成员。Swift 包中的 WorkbenchCore 只依赖 Foundation，包含可版本化的工作区、二叉布局树与持久化结构。Windows 后端可以复用这些数据概念，并在本机重新建立运行期窗口绑定。

真实窗口仍由外部应用持有。后台事件校验当前几何与焦点，布局在用户操作时应用。标签栏使用非激活面板。无法验证崩溃后身份的窗口保留可见，窗口级最小化需要原始状态与恢复记录。恢复时遇到不确定的成员需要用户显式重新绑定。正常退出尽可能恢复；出现恢复冲突时保留日志。

依次验证领域逻辑、拒绝权限时的启动、独立只读探针、打包资源与签名，再用专用测试窗口验证可执行的系统操作。性能结果区分纯计算与跨进程交互。

## 平台契约与持久化

- `WindowDiscovery` 管理枚举和事件订阅，`WindowControl` 提供读取、前置、设置边界和单窗口最小化。显示器提供逻辑点坐标下的可用区域。macOS 实现在各应用的串行队列上访问 AX，主线程消费合并后的快照。
- 每个工作区持有组，组持有分割树与自由浮动成员。窗格里的 UUID 列表有顺序，并保存活动成员。导入时验证节点 ID、组归属唯一性、树深、分割比例和配置版本。
- `workspaces.json` 和 `recovery.json` 是两个独立的版本化 JSON 文件。前者记录用户组织的结构，后者在系统写入前记录恢复依据。未知版本与损坏的本地配置进入只读保护。导入不会替换本机的恢复日志。
- 会话内用 AX 对象相等性识别同一窗口。跨管理器会话恢复需要一组一致的应用标识、进程启动时间、PID、唯一 AXIdentifier。已知存在歧义的标识会被排除。同名窗口不通过标题自动绑定。
- 遇到失败，协调器尝试按逆序撤回本次几何与最小化写入。若还原失败，持久化日志保留下一次重试所需的信息。窗口前后层次、第三方应用的焦点策略、用户临时移动窗口都可能受系统和其他工具影响。
- 布局编辑器允许先调整分割线和组结构，然后显式应用。工作台在组内窗口获得焦点时显示标签栏，离开该组时收起，防止浮层覆盖无关应用。工作区切换默认保留其他窗口的可见性。
- 第一版共享数据协议的样例是通过 `Codable` 编解码的 v1 工作区文件。将来实现其他操作系统后端时，平台需自行提供真实窗口绑定，使用同一坐标约定和布局树语义。

## 界面

三栏分别显示导航、当前工作区或编辑画布、可折叠检查器。原生字体、系统语义色、蓝色选中态与 SF Symbols 支持浅色和深色外观。布局缩略图来自同一分割树。截屏预览仅在用户打开已授权的检查器预览时获取一次，弹层关闭释放图像。


## 工作区激活与恢复事务

侧栏、工作区卡片、快速切换器和菜单栏共用工作区激活命令。当前工作区来自已经提交的 `activeID`，编辑器单独维护正在查看的对象。旧配置的“切换时排布”“最小化前一工作区”两个字段继续用于导入导出，设置页将其呈现为聚焦、排布、专注三个选项。

每次激活先选择各窗格中仍连接且可用的活动成员，再生成显示、移动、调整尺寸和单窗最小化命令。所有布局操作结束后，对其余窗格请求 AXRaise，最后只对一个目标窗口请求应用前置和键盘焦点。目标应用与 WindowServer 决定实际 Z-order。手动最小化的窗口和未连接占位符跳过；目标没有可用窗口时，保留前一工作区的可见性。

创建并应用窗口组、切换工作区、选择标签和撤销都将配置提交放在窗口事务的末尾。只有原子保存成功，模型才发布新的活动工作区、成员或历史记录。若窗口写入或保存失败，协调器尝试撤回本次窗口写入，遇到外部移动或身份变化时保留恢复依据。删除成员的顺序不同：先持久化解除归属，再恢复该成员的原始位置和受管最小化状态。如果恢复失败，归属已经删除，日志保留，可在设置中重新执行恢复。

对话框、用户最小化窗口、不可调整尺寸或身份不稳定的窗口分别按能力判断。需要最小化的标签只有在运行中身份可唯一匹配、支持该属性时才执行。占位符重连只更新布局归属；旧进程的日志独立保留。工作台通过用户明确确认才请求系统启动指定缺失应用。
