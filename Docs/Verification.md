# 本机验证

验证环境为 Apple M4、macOS 27.0.1、Apple Swift 6.1.2。Release 可执行文件的 LC_BUILD_VERSION 最低系统为 14.0，链接 SDK 为 15.5。

| 路径 | 验证结果 |
|---|---|
| 双击可运行的本地签名应用 | 通过 LaunchServices 打开，启动时一个管理中心窗口，“工作区”菜单能打开快速切换器 |
| 布局与恢复测试 | Swift Testing 检查分割树、模板、几何、重复归属、用户最小化、错误身份、写前日志、事务失败回滚和外部改动 |
| 真实窗口完整流程 | 两个独立签名的测试应用，各两个同名窗口。跨进程添加标签、双向聚焦、切换工作区、撤销切换和退出后四个窗口的几何及最小化状态均通过验证 |
| 新观察器恢复 | 重新枚举并匹配写入磁盘的恢复记录，恢复目标窗口，复查同进程兄弟窗口 |
| 无响应应用 | 向自建测试进程发送 SIGSTOP，收到有界 AX 超时，再用 SIGCONT 恢复并重新读取窗口 |
| 管理中心交互 | 隔离的原生测试窗口验证双击进入编辑器、鼠标拖动修改分割比例、选择窗口加入组、新建窗口组 |
| 只读第三方应用抽查 | 当前桌面的 Chrome 窗口报告可移动、可调整尺寸，未提供可靠持久标识。当前扫描未取得以 Codex、Claude Code、OpenChamber 命名的可测试窗口。命令行工具使用其终端宿主窗口 |
| 性能 | 见 [性能报告](Performance.md)，分别记录夹具基准和管理中心进程的空闲取样 |

macOS 14 真机、Intel、实际睡眠/锁屏/热插拔、Stage Manager 共存、开发者签名分发和公证均未做发布验收。实际截屏授权、登录项注册以及全部上下文菜单、跨面板拖放组合仍需交互验收。测试窗口不代表所有第三方应用对 AX 的响应方式。
