## 发布后实窗兼容性检查

Finder、Chrome、Codex、Claude 与 OpenChamber 的新建窗口已参与真实 AX 测试。各应用验证的动作、版本和窗口限制见[实机验收记录](ManualAcceptance.md)。独立管理中心测试窗口还验证了两个入口：单击工作区摘要会提交激活，双击同一摘要会打开布局编辑器并保留原活动工作区。测试既读取界面辅助功能树，也核对临时配置中保存的活动工作区。

代码提交 `07a9ec0` 通过 Debug 构建、50 项自动化测试、严格格式检查和 Release 集成检查。Release 检查使用两个夹具的四个窗口，验证了外部浮条、工作区和标签撤销、失败反馈、退出还原及新观察器恢复，退出码为 0。

## v0.2.0 发布后回归

审查范围从项目主页提交 `a63954d` 到发布标签 `v0.2.0`（`9476b9a`）。发布版原有 41 项测试通过。另用模拟控制器注入窗口关闭、应用限制尺寸和配置保存失败，并在临时 QA 环境复查实际标签条。

| 原先可复现的行为 | 修复后的通过条件 |
|---|---|
| 切换过程中后台标签关闭，或所选窗口无法达到目标尺寸 | 仍能聚焦可用的目标窗口。最终聚焦失败时不提交标签选择 |
| 应用只接受部分尺寸，之后保存配置失败或可见窗格排布失败 | 对可归因于本次操作的几何变更，按实际接受的尺寸回滚 |
| 还原专注工作区时，刚从程序坞恢复的测试窗口只移动，未达到目标大小；退出时也可能只还原一半几何 | 两项几何都改变时分步写入，在进程队列上核对第一步的边界仍然稳定，再完成另一项。集成测试回读工作区边界，退出时再逐窗核对原始位置和尺寸 |
| 从其他工作区选择标签时忽略「聚焦」模式，快捷键停在用户最小化的标签上 | 跨工作区遵守所选模式，键盘向前、向后都跳过不可用窗口 |
| 用户自行还原窗口，已打开的设置页仍显示过时的恢复条数 | 恢复日志变动通知订阅该值的界面 |
| 同一应用的另一个窗口移动，活动标签条也会短暂消失 | 独立 QA 测试分别移动同进程的两个窗口，只有活动窗口的移动会收起该浮条 |
| 布局间距拖动中停顿产生多次撤销，或键盘调整后立即离开设置导致改动丢失 | 一次拖动保存一次，离开设置时提交尚未保存的调整 |

管理中心还修正了搜索当前工作区、选择结果后仍停留在搜索页的问题。当前卡片通过「编辑布局」进入编辑器。Finder、浏览器、第三方开发工具、台前调度与多屏组合的实机验收继续见[验收清单](ManualAcceptance.md)。

2026-11-22，提交 `ecda7cf` 通过 Debug 构建、全部 50 项自动化测试及严格格式检查。在 macOS 27.0.1 运行带计时的 Release 集成检查，退出码 0。两套夹具的四个真实窗口通过外部标签条点击、兄弟窗口移动隔离、重复工作区切换、撤销、组重排与退出还原。暂停夹具后 547.0 ms 得到失败反馈，恢复进程后可以继续操作。全新观察器通过磁盘恢复与兄弟窗口隔离检查。

## 标签移出与新组排布回归

新增的五项测试覆盖前台标签移出后由可用窗口接替、跳过用户最小化的标签、后台移出时保留键盘焦点、接替失败时回滚、新组与已排布组共享显示器，以及转入浮动组后恢复原组剩余窗口。新增分屏组时还注入目标聚焦失败，核对原组几何和配置都可恢复。全部 34 项单元测试通过。

Release 隔离集成测试在两个专用应用中实际移出前台标签、将活动成员转入浮动组并撤销、在同一显示器新建第三组。测试通过 AX 回读焦点、最小化状态和边界，最后检查四个窗口恢复原始状态。真实第三方应用的兼容性继续按 [手工验收清单](ManualAcceptance.md) 记录。

## 第二轮审计与复现

| 检查项 | 复现与修复 |
|---|---|
| 配置写入失败、撤销 | 将临时配置文件替换成不能写入 JSON 的目录。旧实现把撤销计为成功并丢失历史。现在保留原状态和历史，移除故障后可重试。 |
| 重新绑定 | 旧实现会在保存之后再次写入已有的相同绑定。未复现真实窗口被错误替换。删除冗余写入，测试验证保存失败时组、绑定、历史、恢复日志保持一致。另复现浮窗重连丢失相对坐标，已单独修复。 |
| 分屏聚焦 | 三窗格测试在命令索引 2、5、8 各发现一次键盘聚焦。修复后先排布和前置可用成员，最后只有一个键盘焦点目标。 |
| 标签切换 | 目标在执行期间关闭或被用户最小化时，旧流程可能跳过最终聚焦并提交切换。现在拒绝提交，尝试恢复先前标签；切换标签的撤销会选回之前的活动标签。 |
| 解散和移除 | 原来的 `isDisjoint` 判断读取提交后的状态，未复现“恒为 false”。以配置提交的 Result 驱动后续恢复。未写入配置时保留归属；保存后 AX 恢复失败时保留日志，可重试。 |
| 拖动到失效窗格 | 原流程先移除旧成员再尝试插入过期目标。回归测试确认成员会丢失。现在先验证目标，再提交转移。 |
| 过期的焦点和可见性 | 两个进程的观察快照都携带旧焦点时，可误改后台组的选中标签。现在按前台 PID 过滤并发布聚焦回读。另一条回归在刚释放窗口后立即重组：观察缓存仍显示最小化，旧计划漏排首窗并聚焦了另一窗。创建时主动回读所选成员，重新核对运行期绑定。 |

第二轮单元测试使用模拟窗口控制器、临时配置目录和注入的权限状态。未连接、同名、缺少唯一标识、拒绝权限、写入失败、焦点失败、进程退出和恢复重试分别有可重复断言。真实应用验收步骤见 [手工验收清单](ManualAcceptance.md)。

### 本轮实测

- `swift build`、`Scripts/test.sh`、`Scripts/lint.sh` 通过，Swift Testing 共 29 项。
- `Scripts/integration-check.sh release` 返回 0。QA 管理中心使用独立应用标识和临时目录，只控制两个自建应用的四个同名窗口。跨应用标签、真正的浮条按钮 AXPress、标签和工作区撤销、多轮切换、删除工作区后立即创建并应用新组通过。叠放标签连续切换期间浮条不被收起再弹出；直接移动活动窗口后，浮条先离开，再在停稳的位置恰好出现一次（`strip_follows_window`）。把切换期间的保持时间临时设为 0 做对照时，前一条断言按预期失败。
- 暂停一个已核对 PID、启动时间与 bundle 路径的夹具进程后，管理中心在 354.3 ms 内报告失败，活动工作区保持原值。恢复进程后可再次聚焦。管理器正常退出后四个窗口的几何和最小化状态恢复，独立观察器从磁盘恢复的检查也通过。
- 管理中心命令耗时、界面模型确认、真实 AXPress 单次计时和空闲 CPU/RSS 分别见 [性能报告](Performance.md)。跨应用标签和专注切换仍受系统最小化动画影响，压力测试期间出现过一次未确认状态。
- 拒绝权限使用注入测试，在常用账户未变更系统授权。Finder、第三方应用、台前调度、多个真实显示器拔插、VoiceOver、不同系统版本仍待人工验证。按需预览只在打开弹层时启动捕获，关闭后释放图像；本轮没有仪器验证隐藏窗口的合成器绘制次数。

## 第一轮记录（历史）

验证环境为 Apple M4、macOS 27.0.1、Apple Swift 6.1.2。Release 可执行文件的 LC_BUILD_VERSION 最低系统为 14.0，链接 SDK 为 15.5。

| 路径 | 验证结果 |
|---|---|
| 双击可运行的本地签名应用 | 通过 LaunchServices 打开，启动时一个管理中心窗口，“工作区”菜单能打开快速切换器 |
| 布局与恢复测试 | Swift Testing 检查分割树、模板、几何、重复归属、用户最小化、错误身份、写前日志、事务失败回滚和外部改动 |
| 真实窗口完整流程 | 两个独立签名的测试应用，各两个同名窗口。跨进程添加标签、双向聚焦、切换工作区、撤销切换和退出后四个窗口的几何及最小化状态均通过验证 |
| 新观察器恢复 | 重新枚举并匹配写入磁盘的恢复记录，恢复目标窗口，复查同进程兄弟窗口 |

### 侧栏、权限和窗口选择回归

- 在无窗口组的隔离工作区，点击「布局模板」行文字右侧，确认出现「暂无已保存的模板」。在设置中点击「关于」行右侧，确认出现版本说明。两个落点均在旧版复现失败，修复后通过。
- 在隔离的窗口选择器中注入两个普通窗口，确认「可选窗口 · 2」与「已选窗口 · 0」同时显示，勾选后变为「已选窗口 · 1」。模拟无权限时显示授权说明。单元测试覆盖权限撤回后到达的旧快照，以及再次授权后恢复发现。
- 实际下载副本的系统授权仍需通过 macOS 的隐私面板授予。在系统设置中切换真实授权后，切回 workstack，检查提示与窗口列表是否立即更新。
- 使用下载包验收授权时，记录实际启动的应用位置及签名。测试宿主的授权不能代替对下载副本的检查。
- 在本机清除旧副本、偏好和缓存后，以同一签名重新安装到 `/Applications/workstack.app`。复现系统辅助功能开关已开启、当前进程仍报告未授权。仅重置该应用的辅助功能记录并重新申请后，正式进程的选择器显示「可选窗口 · 2」和「已选窗口 · 0」，授权提示消失。侧栏「布局模板」及「所有窗口」也在该进程中通过切页检查。
