# macOS 实机验收

### 已完成的实窗检查

2026-11-22 在 Apple Silicon、macOS 27.0.1 上使用临时工作区配置。写入对象限于本次新建的窗口。测试通过管理中心使用的 Workbench 命令调用真实 AX 后端，并回读系统焦点和窗口边界。

| 实际应用 | 操作与结果 |
|---|---|
| Finder 27.0、Chrome 158.0.8127.36 | 两个新 Finder 窗口分别指向带有测试标记的空目录，Chrome 使用临时用户配置。一个 Finder 窗口与 Chrome 编组，双向切换标签并撤销，在两块屏幕上分别应用左右分屏。解散后核对两个成员的原始边界、最小化状态、恢复日志和未加入组的 Finder 窗口，全部通过。 |
| Codex 桌面端（`com.openai.codex`，26.1117.41037）、Claude Desktop 6.28899.6 | 分别通过原生菜单「新窗口」和「New Session in New Window」创建测试窗口。双向切换标签时核对应用的 AX 焦点对象、叠放位置和可见性。撤销选回前一窗口，解散后测试窗口和原有兄弟窗口的几何与最小化状态通过检查。此次两个窗口均缺少可用于崩溃恢复的稳定身份，使用默认叠放。 |
| OpenChamber Desktop 2.7.2、Finder | OpenChamber 使用临时 Electron 配置和独立数据目录，预建空项目目录并关闭 OpenCode 服务启动。跨应用叠放、撤销、在两块屏幕上分屏、解散和原位还原通过。在 1470 点宽的屏幕上，均分方案请求 731 点，OpenChamber 实际接受 800 点。工作台报告尺寸不匹配并回滚，将分隔比例调到 42% / 58% 后可成功应用。 |

上述显示器测试覆盖已有两块屏幕之间的布局分配。物理拔插、系统 Spaces、macOS 14 真机与 VoiceOver 朗读仍待专门验收。台前调度已按本轮范围暂缓。

### 后续手工验收清单

以下组合可在专用 macOS 登录账户中新建无重要内容的窗口验证。夹具实测与平台覆盖情况见[性能报告](Performance.md)及[验证记录](Verification.md)。

记录系统版本、设备、屏幕排列与缩放、Stage Manager 开关、workstack 版本、目标应用版本、操作入口。用屏幕录像记录焦点跳动或遮挡，截图前关闭包含个人信息的窗口。

| 场景 | 操作 | 通过条件 |
|---|---|---|
| Finder | 建两个同标题窗口并编入同一窗格，通过标签条切换、撤销，再删除组 | 每次只有目标窗口获得键盘焦点。撤销恢复前一标签。删除后可在原位置使用两个窗口 |
| Safari、Chrome | 各建两个独立浏览器窗口，在浏览器内再创建原生标签。将不同进程的窗口编组，切换两次 | 针对选中的浏览器窗口操作，原生标签和同名兄弟窗口的内容保留 |
| Codex Desktop、Claude Desktop Code、OpenChamber | 每个应用各打开两个可独立移动的项目或对话窗口，与 Finder 交错分组。从侧栏、快捷切换器、外部标签条分别进入，核对光标及前台应用 | 只聚焦选中窗口。应用只提供单个系统窗口时记录可发现数量。记录不允许缩放、聚焦或缺少稳定标识时的提示和回退行为 |
| 搜索和编组 | 全局查找一个未绑定窗口；从搜索结果和窗口库分别加入已有组、新建组；在同标题候选之间选择 | 用户能在提交前辨别目标；持久化后仍指向同一成员。取消不会改变原组 |
| 重复切换 | 两个工作区各建多个分屏、标签窗格和浮窗；三种模式分别交替进入至少十次，通过侧栏、卡片、快速切换器和菜单栏各进入一次 | 只聚焦保留几何；应用布局保留前一工作区可见性；专注模式只收起可安全恢复的旧成员。最终前台窗、选中工作区和磁盘状态一致，其他窗格无逐个争抢焦点 |
| 系统全屏、用户最小化、隐藏或关闭 | 先手动最小化一个兄弟窗口，再将另一个全屏或隐藏应用，切换后关闭和重开一个同标题窗口 | 手动最小化和系统全屏状态受到保护。关闭后保留未连接占位，新窗口重新关联后才受控，提示可定位失败 |
| Stage Manager | 开关台前调度后分开和组合两个应用，跨组切换，检查标签条、回退及退出 | 记录系统自身的换组动画及可重现差异；标签条跟随当前可操控窗，退出后无残留悬浮条 |
| 多显示器和 Spaces | 在两块不同缩放、不同方向或带负坐标的屏幕各建一组，切换空间、移动目标窗、拔下副屏再撤销 | 焦点、标签条与目标窗处于同一显示器和当前空间，回退后的标题栏位于可见区域。记录系统的“显示器具有单独的空间”设置 |
| 删除、退出与恢复 | 在专注模式先删除非活动组或工作区，核对隐藏成员，再正常退出；在专用账户中单独测试异常退出后恢复 | 原窗口几何和 workstack 代管的最小化恢复。用户另行移动或最小化的窗口保留用户状态；同名兄弟窗不继承失联窗口的恢复记录 |
| 拒绝辅助功能权限 | 在没有为测试副本授权的账户启动，打开窗口库并执行需要 AX 的操作 | 界面可启动并给出权限状态。失败操作不会提交新的活动工作区，测试不改动常用账户的授权 |
